# D4 — Detector improvements

**State:** in progress

## Goal

Raise balanced accuracy and temporal accuracy by fixing the failure modes found
in D3. Develop only on train/dev (the old test split now counts as dev data).

## Approach

1. **D6 reachability evidence.** Give the investigation a reachability fact: a
   `check_reachability` tool (call-graph `reachable_from` plus guard-literal
   analysis), so disabled or unreachable compliance code is distinguished from
   absent code. Teach the class arbitration that present-but-unreachable is D6
   and absent is D2.
2. **D7 vs D2.** Before choosing D2, require an explicit search for the
   required outcome (grep for the outcome literal or paragraph, plus a slice of
   the outcome variable). If it is found and reachable, D2 is not allowed.
3. **Temporal.** State the clause version and effective date prominently and
   require the comparison against that version's `current_value`.
4. **Claim wording for entailment.** Guide the `claim` field toward a
   paraphrase of the clause obligation, so the citation check passes for
   correct findings (D6 especially).

## Done when

Offline tests cover each new tool and guard, and D5 dev runs show the effect.

## Progress

- 2026-10-07: prompt changes in `detector-v3` — claim quotes the clause's
  obligation sentence; D6 requires checking every assignment to the guard
  field across programs (present-but-disabled is D6, absent is D2); D2
  requires an explicit search for the required outcome first; judge only
  against the supplied clause version. `search_regulations` removed from the
