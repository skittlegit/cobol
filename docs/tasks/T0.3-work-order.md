All models: Pydantic v2 `BaseModel`,
`model_config = ConfigDict(extra="forbid")`.

### `DriftType` (canonical literals — consumed by Track B mutate.py and eval)

```python
DriftType = Literal[
    "D1_stale_threshold",
    "D2_missing_rule",
    "D3_contradictory",
    "D4_stale_reference_data",
    "D5_boundary_error",
    "D6_dead_code",
    "D7_conformant",

```

### `CurrentValue`

- `kind: str` — e.g. `"duration_years"`, `"amount_inr"`, `"enum_set"`. Free
  string; the kind vocabulary is not frozen (Track B extends it in T2.1).
- `value: Any` (JSON-serializable).

### `RegulationClause`

- `doc: str` (required)
- `clause_id: str` (required)
- `version: str` (**required** — never optional; temporal axis is the novelty)
- `effective_date: datetime.date` (**required** — same rationale)
- `text: str` (required)
- `current_value: CurrentValue | None = None` — Optional because D2/D6 clauses
  mandate a _check_, not a scalar. D1/D4/D5 instances should carry it (not
  schema-enforced in v1; enforced by the T2.3 generator).

### `CodeLocus`

- `programs: list[str]` (min length 1)
- `paragraphs: list[str]`
- `line_span: tuple[int, int]` — validator: both ≥ 1, `start <= end`
- `slice_vars: list[str]`
- `is_interprocedural: bool` (**required**, no default — it drives the headline
  stratification and must be a deliberate annotation)

### `Labels`

- `program_level: Literal["drift", "conformant"]`
- `paragraph_level: Literal["drift", "conformant"]`
- `line_level: list[int]` — empty list for conformant instances

### `Provenance`

- `source: Literal["synthetic", "real_curated"]`
- `base_program: str`
- `mutation: str | None = None` — required-in-practice for synthetic (validator
  below), absent for real_curated
- `annotator_notes: str | None = None` — for the real-curated seed (T2.5)

### `DriftInstance`

- `instance_id: str` — pattern `^drift_\d{6}$`
- `regulation_clause: RegulationClause`
- `code_locus: CodeLocus`
- `drift_type: DriftType`
- `labels: Labels`
- `gold_rationale: str` (required, non-empty)
- `provenance: Provenance`

**Cross-field validators on `DriftInstance` (model_validator, mode="after"):**

1. `drift_type == "D7_conformant"` ⇒ `labels.program_level == "conformant"`,
   `labels.paragraph_level == "conformant"`, and `labels.line_level == []`.
2. `drift_type != "D7_conformant"` ⇒ `labels.program_level == "drift"`.
3. `provenance.source == "synthetic"` and `drift_type != "D7_conformant"` ⇒
   `provenance.mutation` is not None (a synthetic drift must record how it was
   made; MO-0 conformant instances may also record their benign edit but are not
   required to).

### Part 2 — explicit response contract and one repair turn

The response prompt and generated schema must say that `kind="finding"`
requires both `prediction` and `claim`. `claim` is the proposition checked by
the verifier; `prediction.rationale` explains the detector's classification
and must not silently replace a missing claim.

Extend the internal `AgentResponse` replay shape with:

```python
raw_provider_text: str | None = None
contract_error: str | None = None
```

Every live adapter stores the exact provider text in
`raw_provider_text`. A parsing or Pydantic contract rejection returns a typed
abstention with `contract_error` set; semantic abstentions and provider/network
failures leave it `None`. Never detect a contract failure by matching an
abstention-reason string.

Implement one provider-neutral contract-repair turn per trajectory/hunt:

1. Persist the rejected response, raw text, validation error, and token count.
2. Re-prompt once with the validation error, the original response contract,
   and an instruction to return a complete replacement object.
3. Persist the repair response too.
4. Accept a valid repaired tool/finding/semantic abstention. If the repair is
   rejected, abstain fail-closed.

The repair applies to returned provider text that fails JSON or the response
schema; it does not retry authentication, quota, HTTP, or transport failures.
Those remain typed infrastructure failures under the existing provider retry
policy.

Add `max_contract_repairs: int = 1` to `BudgetSpec`. Repair attempts count
toward token and wall-clock budgets and are included in
`Trajectory.model_responses`, but do not create an extra semantic tool/finding
step. Update replay/budget assessment so it separately checks semantic steps
and contract repairs; a repair must never bypass any budget.

### Part 3 — investigate before agent abstention

This rule applies to agent hunts only, not single-shot baselines.

- A hunt may accept abstention only after at least one successful tool
  observation. A tool call with an error is not successful.
- Any pre-evidence abstention, whether on turn one or after failed tool calls,
  is persisted and re-prompted with a reminder naming the available tools and
  the authorized program scope.
- Repeated pre-evidence abstentions consume normal step/token/time budgets and
  eventually end in budget-exhausted abstention; they must not create an
  unbounded retry path.
- After one successful tool observation, abstention remains a legitimate,
  first-class result. Do not coerce a finding.

Update the system/hunt prompts to state that code is absent from the prompt and
must be acquired through `read_paragraph`, `read_program`, `slice_on`,
`trace_variable`, `grep`, or another available typed tool.

Only the program scope may be named. Do not expose the gold paragraph, line
span, insertion point, drift type, mutation, or rationale. The external draft's
request to name the instance's paragraph scope is rejected because it would
leak a localization label and violate T4.1's gold-hidden gate.

### Part 4 — preserve all hunts and enforce run validity

`investigate_all_hunts()` currently returns one `HuntOutcome` and discards the
other six trajectories. Replace that return with a typed batch result
containing all seven outcomes plus the selected outcome. Persist all seven in
each agent `EvaluationRecord` through a typed agent-hunt trace field. Baselines
leave that field empty. Selection and verified-emission semantics remain
unchanged.

Compute run validity from the complete persisted evidence, not only the
selected trajectory. Add a typed validity block to `RunManifest` with at
least:

- completed/available row count;
- provider-turn count;
- contract-rejection count and rate;
- non-null verified-prediction count and rate;
- for agent runs, successful tool-call count and mean per row;
- status plus explicit reasons.

Frozen definitions:

- `contract_rejection_rate = rejected provider responses / all provider
  responses`, including rejections recovered by repair;
- `non_null_prediction_rate = final verified predictions / available rows`;
- agent `mean_tool_calls = successful tool observations across all seven hunts
  / available agent rows`.

Frozen validity outcomes:

- contract-rejection rate above 0.10 after at least five provider responses:
  halt before the next paid row and report
  `HALTED_CONTRACT_REJECTIONS`;
- agent mean successful tool calls below 1.0:
  `INVALID_AGENT_RUN`;
- final non-null prediction rate exactly 0.0:
  `NOT_EVALUABLE`;
- otherwise `VALID`.

Report every failed gate even when one status takes precedence. Zero
infrastructure failures is still required but is not sufficient for validity.

The CLI lives in `eval/live.py`, not `eval/run.py`. Add `--smoke N` there;
keep reusable validity computation in `eval/run.py`/`eval/schemas.py`.

- Smoke selection is the first N rows in frozen split order; no post-hoc row

- Smoke artifacts/manifests are separate from headline artifacts.
- A full run must refuse to start unless a successful smoke manifest exists
