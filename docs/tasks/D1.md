# D1 — Host-computed evidence-ledger hashes

**State:** done (2026-10-07)

## Problem

The old prompt told the model to copy each observation's 64-character SHA-256
into its evidence ledger. The model mis-copied four of them (cases 154 and 173,
and temporal case 040). That failed the provenance check and made the whole run
`NOT_EVALUABLE`. It also caused 6 additional abstentions.

## Change

The model cites observations by tool-call sequence number only
(`SubmittedLedgerNote`). `detector.host_ledger` attaches the hash computed from
the host's trusted tool log. The answer schema has no hash field.

## Done when

`tests/test_detector.py` shows that the schema has no hash field, the prompt
never asks for hashes, and host hashes equal the SHA-256 of each trusted
observation.
