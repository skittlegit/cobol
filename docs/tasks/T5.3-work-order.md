## Objective

Complete the benchmark-first comparison suite without changing the agent,
verifier, M4 prompts, or benchmark labels in response to results. Every
baseline receives only the information declared below and runs over the exact
frozen T5.2 test order.

## Frozen suite

The seven baselines are:

1. **Train-majority:** full-coverage binary verdict fixed from the frozen train
   prevalence.
2. **Prevalence-random:** deterministic SHA-256 draw per instance against the
   same train prevalence; seed identity is `m5-random-v1`.
3. **Static/keyword:** deterministic clause-value and content-token matching
   against materialized source, with no labels, mutation metadata, retrieval,
   model, or edit-history cues.
4. **Plain single-shot LLM:** clause plus bounded code context, no retrieval,
   tools, loop, oracle variables, or prior prediction.
5. **Dense-RAG single-shot:** explicit dense retrieval plus the same bounded
   code context and one model turn.
6. **RAG+reranker single-shot:** explicit hybrid retrieval and cross-encoder
   reranking plus the same bounded code context and one model turn. The M4
   artifact historically named `dense_rag` used `RegulationSearch`'s pinned
   `hybrid_rerank` default and is this baseline when its input identity matches.
7. **Attacker with bases:** the exact registered six-feature logistic probe
   fitted on `t2.2_surface_probe.jsonl`, applied to base/current source pairs.
   It may diff against published bases but receives no class, operator,
   mutation note, gold rationale, or label.

The agent is the headline system and oracle-slice remains a separately reported
deconfounder; neither is counted among the seven baselines.

## Predeclared surface-floor rule

Before any M5 headline result, the agent is required to beat the
attacker-with-bases baseline by at least **+0.10 binary T1 F1**, with the paired
bootstrap 95% interval on agent-minus-attacker excluding zero. This is an
evaluation-integrity floor, not a replacement for the CONTRACT headline bars.

## Gates

- All offline baselines are deterministic under reordered input and never read
  gold until constructing the paired evaluation record.
- Static/keyword and attacker inputs contain no provenance mutation, operator,
  labels, rationale, edit history, mtime, or comment-freshness features.
- The attacker uses all and only the six registered T2.2 features and records
  its fitted coefficients and source-probe hash.
- Provider baselines use the same frozen model family, reasoning effort,
  schema, verifier, bounded context, and test order. Smoke validity gates run
  before full execution.
- Every emitted LLM finding passes the unchanged T3.4 verifier; abstentions
  count as misses.
- Results report binary T1 overall and per locus stratum, answer rate,
  classification where structured output exists, and paired intervals.

## Exclusions

- No tuning against test results.
- No change to verifier thresholds, evidence minima, prompts, or labels after
  observing a baseline score.
- No provider run before the immutable T5.2 split exists.

### Finding A — degenerate attacker: the surface floor is a prevalence floor

The all-zero fit is not a fitting bug. The T2.2 probe is balanced *exactly*: for
each of the six features the 50 drift rows and 50 MO-0 rows have **identical
sorted value multisets** (per-feature AUC 0.5 for all six, not merely the
aggregate 0.50). The gradient contributions therefore cancel and
`_train_logistic` converges to weights = 0, bias = 0. `predict` is
`int(score >= 0.0)`, so every instance scores exactly 0.0 and is predicted
drift, and `attacker_with_bases` is numerically identical to `train_majority`.

Consequence for the **predeclared surface-floor rule**: the attacker's binary T1
F1 is 0.8768, driven entirely by the 78.1% test drift prevalence, so the rule as
written requires the agent to reach **≥ 0.9768** T1 F1. That is not the
surface-cue floor the rule was written to impose — it is a prevalence floor,
and a stricter one than any CONTRACT headline bar.

This is reported, **not fixed**. Changing the probe, the fit, the tie-breaking
threshold, or the floor arithmetic after seeing a baseline score is exactly what
the Exclusions section prohibits, and the T2.2 probe artifact is Track B's. The
floor rule needs an explicit, predeclared decision in the track chat before the
M5 headline is computed. Options, none adopted here: (a) keep the rule and
accept it as a prevalence floor, restating it as such; (b) predeclare a
tie-breaking convention (`score > 0.0`, i.e. abstain-to-negative on a
zero-information fit) before any provider run; (c) rule the comparison vacuous
when the fitted attacker carries zero weight on every feature, and report the
degeneracy itself as the anti-gaming evidence. (c) is the closest to what the
T2.2 probe was built to demonstrate.

## Amendment — Finding A resolution (2026-08-11)

**Ratified: Finding A option (c).**

1. The predeclared **+0.10 agent-over-attacker surface floor is vacated for
   T5.4**. The fitted attacker carries zero weight on every one of the six
   registered features, so the comparison measures test-set prevalence, not
   surface cues, and cannot discharge the evaluation-integrity purpose the floor
   was written for.
2. The `attacker_with_bases` artifact is **retained as null evidence** for the
   T2.2 probe's anti-gaming construction. Its value is the degeneracy itself:
   an attacker given base/current source pairs and the full registered feature
   set fits to all-zero weights, which is what the probe was built to
   demonstrate.
3. The paired **agent-minus-attacker delta is dropped from T5.4's headline
   reporting**. T5.4 reports the attacker as null evidence with its coefficients
   and probe hash, not as a floor the agent must clear.
4. The **T4.5 §8.4 hard-stop rule against post-hoc knob changes** governs from
   this point: no adjustment to the T2.2 probe, the fit logic, or the decision
   threshold is permitted. Option (c) is a reporting decision made *before* any
   provider baseline exists; it is not, and must not become, a licence to retune
   the instrument after seeing a score.
