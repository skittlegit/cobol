# E3 — Third evaluation: fresh test split and temporal pairs, same detector

**State:** done — NO_GO

## Why

E1 (NO_GO) and E2 (GO, post-hoc) left four known problems: three temporal
programs still had flaws, and test D6 recall was 4/22. Inspecting the D6
misses showed they came mostly from the benchmark, not the detector: the
batch-chain hosts linked their two steps only implicitly (DISPLAY in one
program, ACCEPT in the other) and excluded unpaid charges but not unpaid
levies and taxes from the interest base. Because the E1/E2 test split and
temporal pairs had been inspected, they cannot give a first-look estimate any
more. E3 is a fresh evaluation.

## What changed before the run (all on train/dev or new data)

- The E1/E2 test split (145 rows) and temporal pairs (44 rows) moved into dev
  (now 509 rows). In dev: the 20 chain hosts were corrected (the accrual step
  CALLs the run-control module; the base excludes charges, levies and taxes)
  and their 34 rows rebuilt; TPCO02/TPCO07 now name control of management or
  policy explicitly; TPCO04 compares shares exactly instead of a rounded
  percentage.
- The frozen detector was measured on the corrected dev chains (46-row subset
  at `high`): D6 17/20, balanced accuracy 0.898 on the subset. No detector
  change was made.
- New test split: 110 seed programs in `seed/programs/e3/` with new designs
  (refund-cutoff hosts using FUNCTION MIN and EVALUATE; over-limit gates with
  an explicit-consent route; closure-penalty chains whose penalty step CALLs a
  run-control module; 18 local hosts), each compiled and behaviour-checked on
  every clause leg (231 checks). 117 candidates; Claude judged 116 plausible
  (one D2 deletion that can never breach the clause rejected). 116 rows, 45
  cross-program. Leakage: no base group, row id, or detector-visible source
  shared with train/dev. Every row compiles.
- New temporal pairs: 22 new programs (company 10, trust 7, partnership 5),
  each implementing every leg of its clause with the 2016 threshold, checked
  with 79 behaviour tests; both sides of every pair materialise to identical
  source.
- The clause record for paragraph 19 now lists MO-6× as a legal operator.

## Protocol (fixed before any E3 result)

- Detector unchanged: every method file (all of `src/`, the vendored grammar,
  and the NLI cache) is byte-identical to commit ea5db367, checked file by file
  against the commit's blobs before the run. gpt-6-luna at effort `max`. Gates
  unchanged.
- Amendment before any result: a first launch was stopped within a minute,
  having written no records, because `codex.method_hash()` differed from the
  value noted in E2 (5fc235450c18f761). The cause was line endings: git's
  `core.autocrlf=true` had rewritten some working-tree files as CRLF when the
  branch was switched, and the hash reads raw bytes. The files were restored
  to the committed LF content; the run records the resulting hash
  (ced86a2759f8aeb9). The method hash should normalise line endings; that fix
  is deferred so the detector's files stay untouched for this run.
- Run `detector --split test`, `detector --split temporal`, and
  `rag_reranker --split test`, with up to three passes each; further re-runs
  only for infrastructure failures, counted and reported. Then
  `report --split test`.
- E1 and E2 stay on record.

## Result (2026-10-08)

**NO_GO.** Six of seven gates pass, most by a wide margin; the cross-program
advantage over the baseline does not.

| Gate | Measured | Required | Pass |
| --- | --- | --- | --- |
| T1 F1 | 0.961 | >= 0.70 | yes |
| Balanced accuracy | 0.938 | >= 0.65 | yes |
| Answer rate | 0.991 | >= 0.60 | yes |
| Answered accuracy | 0.957 | >= 0.80 | yes |
| Cross-program F1 vs rag_reranker | +0.071, CI 0.023..0.139, p = 0.031, n = 45 | +0.10, CI > 0, p < 0.05 | no |
| Temporal paired accuracy | 22/22 = 1.000 (exact CI 0.846..1.000) | >= 0.70 on >= 20 pairs | yes |
| Unverified findings | 0 | 0 | yes |

Per-class recall: D1 26/27, D2 4/5, D3 16/17, D4 2/2, D5 9/9, D6 15/15,
D7 37/41.

Why the margin gate failed: on the 45 cross-program rows the detector is
perfect (F1 1.000, 45/45), and the baseline reaches 0.929 (39/45, abstaining on
6), so the largest possible margin was 0.071. Every cross-program test row is a
drift case and their drift is visible enough in the bundled source that
retrieval alone finds most of it: a ceiling effect of this test design rather
than a detector error. The decision stands; a future split needs harder
cross-program rows, including conformant ones, for the margin gate to be
informative.

Runs: three passes left one temporal row (drift_190030) failed on
infrastructure (the model typed the bridge path wrongly); it succeeded on a
fourth pass, as the protocol allows. Method hash recorded in every run key:
ced86a2759f8aeb9 (method files identical to ea5db367).
