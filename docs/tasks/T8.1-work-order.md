## Objective

Activate the formerly post-release detector-improvement program before release
and make configuration 3 the current release candidate without deleting or
rewriting configuration 1 or configuration 2 evidence.

Configuration 1 remains the valid historical M4 `NO_GO`. Configuration 2
remains the valid historical smoke hard stop. A valid configuration-3 result
supersedes them only as the current release decision; all three configurations
must remain auditable and must be reported together.

## User-authorized scope change

The user authorized early activation in the project chat on 2026-08-24. This
supersedes the former `M7 complete` scheduling trigger in `BACKLOG.md`.
T7.4/UI remains deferred and is explicitly outside configuration 3.

## Frozen provider identity

- provider/transport: explicitly labeled in-product `collaboration_subagent`;
  it is not native ChatGPT Codex, Codex CLI, or API execution;
- authentication: the existing controlled project-session orchestration; native
  ChatGPT OAuth/account login is not a release requirement;
- model: `gpt-5.6-luna`;
- reasoning effort: `max`;
- reasoning mode: standard (pro mode is not enabled);
- evaluated rows run in fresh isolated subagent tasks with no earlier case or
  result in context;
- this orchestration chat may monitor and resume the run but its transcript is
  never included in benchmark-case prompts;
- exact task identity, prompt/final bytes, prompt/schema/source/tool/verifier
  hashes, authorized tool events, sequential/concurrent group identity,
  repository/runtime snapshot, split hashes, row order, seeds, budgets, and
  batch sizes are recorded before smoke. Native/WSL Codex transports remain
  optional legacy paths and do not gate release.

## Predeclared release-utility gates

Configuration 3 is `GO` only when every validity gate passes and the proper
agent satisfies all of the following on full-coverage scoring:

- T1 F1 at least 0.70;
- balanced accuracy at least 0.65;
- answer rate at least 0.60;
- answered accuracy at least 0.80;
- interprocedural F1 advantage over RAG plus reranker at least +0.10, with the
  paired 95% bootstrap interval excluding zero and paired p < 0.05;
- T6 versioned-judgment paired accuracy at least 0.70 on at least 20 intact,
  independently reviewed pairs; and
- zero unverified emissions and no verifier/evidence-threshold relaxation.

A valid result that misses any gate is `NO_GO`. Missing identity, pairing,
annotation, infrastructure, contract, or required-artifact evidence is
`NOT_EVALUABLE`. Neither outcome authorizes result-driven tuning.

## Controlled-window and resume rule

The smoke starts only after offline gates pass and `run-freeze.json` records
every identity field and selected ID. The managed project session exposes Git
metadata read-only, and the user waived branch restrictions; therefore the
existing HEAD is recorded for ancestry while the executable revision is an
immutable path-and-byte SHA-256 snapshot of `src/**/*.py`, `pyproject.toml`,
and the vendored grammar tree. Any runtime-file change invalidates the freeze
exactly as a commit mismatch would.
The orchestration stays in this project thread and reports progress. Provider
case tasks remain isolated. A ChatGPT usage-limit interruption is recorded as
an infrastructure interruption; it does not change the prompt, sample, or run
key. Execution may resume from completed immutable run keys after access
returns. A long-running thread is not treated as a limit bypass.

Externally orchestrated results enter through the typed
`CollaborationSubagentSubmission` ingestion path and seal as
`CollaborationSubagentExecution`. They are never fabricated or relabeled as
`CodexTaskExecution`. The all-six smoke readiness gate is unchanged.

The transport-independent part of the smoke orchestration is frozen in
`collaboration-smoke-plan.json`: 14 development rows across six systems (84
system-row evaluations) are grouped into 37 isolated tasks with at most three
concurrent tasks. Exact request identities intentionally remain unwritten until
T6 promotion permits `run-freeze.json`; the plan cannot authorize execution by
itself.

## Completion

T8.1 is complete when the freeze artifact is committed, validates against the
runtime configuration, and all downstream work orders consume it without
overrides.
