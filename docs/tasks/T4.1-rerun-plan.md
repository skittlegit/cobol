**Owner:** Track C · **Status:** ratified for ChatGPT Codex smoke ·

This plan replaces the invalid M4 attempt as a future execution plan; it does
not reinterpret or overwrite that attempt. The six artifacts under
`data/eval/m4/` remain diagnostic evidence. Schema-v3 outputs go under
`data/eval/m4-v3/chatgpt-luna/`.

## Frozen configuration

Every smoke, pilot, and promoted full run uses:

- model `gpt-5.6-luna`;
- ChatGPT-authenticated Codex CLI, never API-key authentication; the launcher
  strips `OPENAI_API_KEY`, `CODEX_API_KEY`, `AZURE_OPENAI_API_KEY`, and
  `ANTHROPIC_API_KEY` and refuses a login status that does not name ChatGPT;
- Codex `model_reasoning_effort="medium"`, ephemeral sessions, ignored user
  configuration/rules, a workspace-write sandbox over a data-minimal task
  directory, and no temperature or seed surface;
- prompt `m4-live-codex-batch-v1`, schema version `3`;
- at most two agent cases or five single-shot baseline cases per Codex task;
  provider-token usage is allocated exactly across persisted responses and raw
  Codex JSONL events remain alongside the artifacts;
- agent semantic abstention requires three successful bounded observations;
  one shared real-tool investigation may support all seven hunts for the same
  case, is capped at eight calls, and is replayed into each applicable retained
  trajectory;
- exact structured output via Codex `--output-schema`, followed by the existing
  Pydantic contract, per-class evidence guard, `Finding` construction, and T3.4
  `verify()` gate. No finding persists after any failed layer;
- the same repository commit, input revision, split hash, tool version, and
  per-system budget recorded in each manifest.

The earlier API work may be reused only where it is deterministic and
provider-neutral. Dense-RAG and oracle-slice **contexts** are reused only after
all 204 materialized source SHA-256 values match the prior artifacts.
API-generated predictions, verifier verdicts, manifests, and provider
telemetry are not reused: all three systems receive fresh Luna outputs and are
verified again.

The model or effort level must not change after inspecting results. A change
requires a new predeclared smoke and a complete paired rerun for agent,
dense-RAG, and oracle-slice.

## Luna-low smoke taxonomy amendment — 2026-07-25

The first structurally valid Luna-low agent smoke completed all 5 rows with
zero infrastructure or contract failures and 163 replayed tool observations,
but emitted zero verified findings. Inspection showed a generic taxonomy
interpretation mismatch rather than a tooling or schema failure.

The user authorized continuation with Luna at low reasoning effort. Before any
new live request, the frozen hunt guidance is clarified as follows:

- D1 compares resolved current-value leaves whether their values are scalar,
  list-valued, or enum-valued.
- D2 requires negative grep, caller graph, callee graph, and slice evidence
  before emitting a finding.
- D4 applies only when the clause current value itself is an `enum_set`
  reference collection; an enum-valued business leaf inside a composite
  current value remains D1.

This amendment includes no gold labels, mutation identities, expected loci, or
expected verdicts. All model, effort, sampling, budget, verification, and
promotion gates remain unchanged. If the amended agent smoke again produces
zero verified findings, the run stops rather than introducing another semantic
prompt change.

## Luna-low smoke contract-isolation amendment — 2026-07-25

The amended smoke reached all 5 rows, but a cross-field locus violation in one
submitted hunt caused Pydantic validation of the enclosing provider batch to
fail. The runner consequently marked both rows in that batch as infrastructure
failures. This is too broad: a malformed candidate finding must fail closed,
but it must not erase independent rows or hunts that were validly returned in
the same provider response.

The provider-facing locus DTO now preserves the submitted fields without
enforcing the cross-field `is_interprocedural` rule. Trusted host-input binding
constructs the normative `DriftPrediction`, where that rule remains enforced.
If it fails, the existing no-unverified-emission path converts only that hunt
to an abstention, preserves its raw provider text, and emits no finding. The
host does not correct or reinterpret the submitted flag.

This is a parser isolation fix, not a taxonomy or benchmark change. Model,
effort, prompts, rows, labels, budgets, tools, verification, and promotion
criteria remain frozen.
