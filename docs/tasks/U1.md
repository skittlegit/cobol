# U1 — Update dependencies

**State:** done

Bring the Python packages, the web packages, and the GitHub Actions to their
latest releases, without changing detector behaviour.

## Result (2026-11-08)

Python is on `mcp` 2.3, `torch` 2.15, `transformers` 5.22,
`sentence-transformers` 6.2 and `ruff` 0.17.4, with the minimum versions in
`pyproject.toml` raised to match. The web packages are at their latest
releases, including TypeScript 7. CI uses `setup-python` v7, `setup-node` v7
and `upload-pages-artifact` v5.

`mcp` 2 needed code changes. `FastMCP` became `MCPServer`, and unanticipated
tool exceptions no longer reach the client, so the server now raises
`ToolError` to keep the failure reason. The deploy smoke scripts read the
renamed `is_error` and `structured_content` fields.

Held back: `tree_sitter` stays at 0.21.3 (locked decision 1; 0.26 fails on the
grammar load), and `mpmath` stays at 1.3.0 because `sympy` declares
`mpmath<1.4`.

Checked in WSL: 571 offline tests and 5 network tests pass, against 570 offline
tests on the old packages. Outputs of the NLI verifier, embedder and reranker
on a sample built from all 21 regulation clauses are identical to those of the
previous stack (`torch` 2.14.1, `transformers` 5.19).

Not checked: the deploy smoke scripts, which need a built bundle or container
image. E2 was not re-run, so its numbers come from the previous packages.
