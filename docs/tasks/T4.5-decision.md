# M4 Decision — FIX, not scale

**Owner:** Track C · **Date:** 2026-07-26 · **Discharges:** T4.5 "written
decision to scale or fix" (playbook Phase 4).
**Evidence:** `data/eval/m4/report.{json,md}`, artifacts at commit `357f483`.
**Status of the result:** the NO_GO stands. Nothing in this note revises it.

---

## 1. What the run established

The run is valid: 204/204 on all three systems, zero contract rejections, zero
infrastructure failures, agent mean 3.92 tool calls per row, real predictions
present (agent 47, dense-RAG 132, oracle-slice 101). Independently re-verified
from the committed artifacts on 2026-07-26.

**Solid and significant:** the agent trails dense-RAG on the interprocedural
stratum by **−0.3030** (95% CI [−0.4929, −0.1252], p = 0.00635). The CI
excludes zero. The predeclared GO bars — T1 F1 ≥ 0.70 overall (observed
0.3665) and a ≥ +10 F1 interprocedural win — fail without post-hoc adjustment.
**M4 is a NO_GO and closes the Week-10 checkpoint.**

## 2. What the run did NOT establish (correction of record)

`oracle_slice_deconfounder`: delta −0.1964, 95% CI **[−0.4330, +0.0348]**. The
interval **crosses zero**. Agent versus oracle-slice is **statistically
inconclusive** — underpowered, not a demonstrated slicer win. Oracle-slice
also has the *worst* per-answer accuracy of the three systems (0.218, versus
the agent's 0.681).

Therefore the prior framing line — that this result "directs the next framing
toward the slicer rather than agent-loop superiority" — **over-reads a null
test and is withdrawn.** The playbook's T4.5 reframing rule triggers on the
agent failing to beat oracle-slice; that comparison did not resolve, so the
rule has not fired. Slicer-first remains an open option, not a finding.

## 3. Diagnosis

| Observation | Value |
|---|---|
| Agent coverage | 47/204 (23%) |
| Agent accuracy **when it answers** | **0.681** (best of the three) |
| dense-RAG coverage / answered accuracy | 65% / 0.538 |
| Oracle-slice coverage / answered accuracy | 50% / 0.218 |
| Abstention, interprocedural vs single-paragraph | **75% vs 77% — uniform** |
| Faithfulness by tier | T1 1/6 · T2 **18/25 (0.72)** · T3 **1/16 (0.0625)** |
| T6 paired accuracy | 2/20, exact 95% CI [0.012, 0.317] |

Four readings, in order of confidence:

1. **The agent reasons better than it answers.** Highest per-answer accuracy,
   lowest coverage. Under the full-coverage headline rule (CONTRACT Part 3 —
   correct and **not** to be softened), 157 abstentions score as misses and
   dominate the F1.
2. **Coverage does not explain the interprocedural gap.** Abstention is uniform
   across strata (75% / 77%), so the stratum-specific loss to dense-RAG needs a
   separate explanation. This is unresolved and is the primary open question.
3. **Abstention is not one knob.** Of 157: ~97 substantive model reasoning,
   ~49 citing tool/evidence limits, 11 citing a missing `current_value` leaf
   against only 8/204 clauses that genuinely lack one. At least two distinct
   populations with different fixes.
4. **Tier 3 verification is near-worthless (1/16); Tier 2 is the workhorse
   (0.72).** Tier 1's n=6 matches the risk register's prediction that GnuCOBOL
   cannot execute CICS-heavy code. The tiering design is vindicated: the
   degradation is *visible* because tiers were recorded.

## 4. Decision — FIX

Do not scale. Scaling a system at 23% coverage multiplies cost without
resolving why it abstains.

**Ordered, and the first two are free:**

- **F1 (free, Track C + A).** Triage the ~49 tool/evidence-limited abstentions
  against the committed trajectories. Determine whether they are a tool-layer
  capability gap (→ Track A conversation) or hunt strategy (→ Track C). **No
  paid run may be authorized before this completes** — re-running against an
  unfixed tool gap wastes the budget a second time.
- **F2 (free, Track C).** Resolve open question 2: stratified per-answer
  accuracy and error modes on the 36 interprocedural rows. Why does dense-RAG
  win *there* when abstention is flat?
- **F3 (Track C).** Abstention calibration informed by F1/F2 — not a blind
  threshold change.
- **F4 (analysis only).** Quantify the counterfactual of suppressing
  Tier-3-only emissions: faithfulness rises, coverage falls. Report both.

## 5. Second-configuration protocol (integrity — binding)

The predeclared bars failed. Any subsequent run is a **second, distinct
configuration**, not a replacement:

1. Config 2's changes and its bars are **declared in this file before it runs**.
2. The `357f483` artifacts and this NO_GO remain the record of configuration 1
   and are reported in the paper alongside any config-2 result.
3. Config 2 may use a cheaper or local model. The headline is a **paired
   delta** with the model held fixed across all three systems, so it survives a
   model change; only the absolute T1 F1 ≥ 0.70 bar needs a capable model and
   may be reported separately on one system.
4. Every run passes the `--smoke 5` validity gate first.

Tuning until the bar clears is precisely what predeclaration exists to prevent.

## 6. Consequences for the novelty claim (T0.6 / T7.5)

T6 is 2/20 with an exact 95% CI upper bound of **0.317 — below the 0.5
version-blind floor.** T0.6 declared T6 load-bearing for the novelty sentence,
so **we can no longer claim the system performs versioned judgment.** Note T6
is also coverage-limited: paired accuracy needs both halves answered, and at
23% coverage that is ~5% by chance.

The framing that survives is **benchmark-first**: we pose the temporal
drift task and current agentic methods fail it. This is legitimate and has
precedent — GDPR-Bench-Android's agent likewise underperformed simpler
baselines. T0.6's pre-authorized fallback sentence should be revised: the
"interprocedural slicing as the key enabling capability" clause is **not**
supported (see §2) and must not be adopted by default.
