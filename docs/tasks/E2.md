# E2 — Evaluation after fixing E1's failures

**State:** done — GO

## Why

E1 is the first-look evaluation, and its decision (NO_GO) stands. E2
evaluates again after fixing what E1 exposed. Every fix was made on train/dev
or on new data; the gates are unchanged.

## Fixes since E1

- **Temporal programs.**
  - E1 failed the temporal gate with 15/22 pairs. Several B2 programs tested
    the old threshold but left out part of the clause:
    - share-only tests;
    - no capital route;
    - no control route;
    - a trust test that never identifies the author or trustee.
  - Those programs were corrected in dev.
  - New temporal programs (company 10, trust 7, partnership 5) implement every
    leg of their clause. They are checked with 79 behaviour tests, and both
    sides of every pair materialise to identical source.
- **Batch-chain hosts.**
  - E1's D6 recall was 4/22. The chain hosts linked their two steps only
    implicitly (DISPLAY in one program, ACCEPT in the other), and they left
    unpaid levies and taxes in the interest base.
  - They now CALL a run-control module and exclude charges, levies, and
    taxes. Their rows were rebuilt in dev.
- **Cross-program rows.**
  - Small bundles let retrieval find most drift: the baseline sees 200 lines.
  - The test split's cross-program rows now come from realistic-size programs,
    with bundles of 250–370 lines.
  - Every cross-program host also yields a conformant row, so the stratum
    measures false alarms as well as recall.
- **Clause records.** CC-08a and CC-12b now list MO-6× (a cross-program flag)
  as a legal operator.
- **Infrastructure.**
  - The detector prompt now escapes quotes in every command, including
    `check_finding`.
  - Codex calls rotate across two accounts when one hits its usage limit.
  - The method hash ignores line endings.
- **Baseline.** The rag_reranker prompt now states the same response shape
  the detector is given: a D7 answer has conformant labels and no cited
  lines. Without it, the schema rejected the baseline's conformant answers,
  and they counted as abstentions. On the 48 dev rows this was 19
  abstentions. The fix makes the baseline stronger on conformant rows, which
  makes the margin gate harder for the detector.
- **Detector.** Measured on 48 new realistic-size dev rows in the same four
  cross-program families as the test split. The detector scored cross-program
  F1 0.979 and the fixed baseline 0.375, at effort `high`. No detector change
  was needed, so none was made.

Before E2's test split was written, two intermediate test splits were
evaluated. Once inspected, they were moved into dev, and they now form part of
the dev set this detector was tuned on. Their runs are in the git history,
not in this record.

**Errors.** Nine test rows and two temporal pairs. Several are defensible
readings of how the benchmark programs were written; the decision is not
changed for any of them.

- **Conformant rows called D3 (8).** These are the main weakness: false
  alarms on conformant code.
  - Four bureau-chain hosts (XQCE05, XQEA03, XQMT07, XQPR09). The run-control
    module turns the bureau step on for one region code only. The detector
    reads this as a regional carve-out the clause does not allow. That
    reading is arguable: the region gate is scaffolding in these programs,
    not part of the clause.
  - Two refund-cutoff hosts (XCAT02, XCLY10). `COMPUTE ... ROUNDED` turns a
    cutoff of Rs 1.0055 into Rs 1.01. That is a real edge of the programs'
    arithmetic, the same kind found in E1's TPCO04.
  - XQRU08: an EVALUATE arm order that sends an open dispute to NODISCLOSE.
  - XLGRV05: a response-received route.
- **Missing rule called D6 (1).** XLACT01: the removed assignment left the
  dependent closure branch unreachable, so the detector called that branch
  dead code.
- **Temporal (2 pairs).**
  - pair-09: the old side was called D2, because owners acting together are
    not aggregated.
  - pair-19: the old side was called D3, on how the program spells
    BENEFICIARY.
  - Both new sides were right.
