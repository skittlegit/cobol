# T7.2 work order — air-gapped on-prem deployment bundle

**Owner:** Track A

**State:** ratified 2026-07-28; unblocked

**Depends on:** T7.1 done; M5 is not a dependency

**Canonical artifacts:** `deploy/`, `docs/DEPLOYMENT.md`,
`tests/test_offline_bundle.py`

## Objective

Package the frozen local tool stack and T7.1 stdio MCP server so an operator can
install, configure, and smoke-test it in an air-gapped environment without
changing the ToolLayer contract or downloading code or model weights at
runtime.

## Required deployment profile

1. Build the project wheel with the vendored tree-sitter grammar and pinned
   regulation assets already verified by `tests/test_packaging.py`.
2. Record a machine-readable manifest for Python, GnuCOBOL, package
   dependencies, grammar, regulation sources, embedder, reranker, and NLI model
   identities. Every shipped file or external payload has a version and
   checksum.
3. Provide an offline installation path from a staged wheelhouse/model cache.
   The final smoke must run with hub/network access disabled and fail clearly
   when a required local payload is absent.
4. Provide a non-root container recipe whose runtime stage performs no package
   or model download. The corpus and copybooks are read-only mounts, not image
   layers.
5. Keep stdio as the default MCP transport. Any HTTP profile is opt-in, binds
   to loopback by default, and documents that production TLS, authentication,
   authorization, and multi-tenant isolation must be supplied and tested
   before remote exposure. Do not imply those controls exist when they do not.
6. If an Ollama profile is supplied, it uses a preloaded, explicitly named
   local model and a configurable loopback endpoint. No cloud provider key is
   required for the offline smoke.
7. `docs/DEPLOYMENT.md` covers corpus/copybook configuration, model-cache
   staging, optional GnuCOBOL behavior, startup, health/smoke checks, upgrades,
   logs, and removal.

## Gates

- A clean Python 3.12 environment installs only from the staged local bundle.
- With external network access disabled, `cobol-archaeologist-mcp` starts over
  stdio and exposes exactly the eleven T7.1 tools.
- A fixture corpus exercises `read_program`, `slice_on`,
  `search_regulations`, and the explicit Tier-1-unavailable path without
  downloading anything.
- The runtime refuses a missing corpus, missing required asset, checksum
  mismatch, or uncached requested model with an actionable error.
- The container runs as a non-root user and does not embed corpora, credentials,
  provider logs, benchmark gold, or local caches.
- Existing T1.6/T7.1 contract tests, full offline pytest, Ruff, and
  `git diff --check` remain green.

## Exclusions

- No ToolLayer signature, schema, benchmark, verifier-threshold, or evaluation
  change.
- No claim of production-ready remote or multi-tenant security without a
  separate threat model and end-to-end security gates.
- No provider call or paid evaluation run.

## Completion

T7.2 is done only when the tracked recipe, manifest, deployment guide, and
offline smoke gates reproduce from a clean staging directory. A locally
working editable install is not deployment evidence.
