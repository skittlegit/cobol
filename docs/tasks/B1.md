# B1 — Fresh held-out test split

**State:** todo

## Why

The current `test.jsonl` has been evaluated repeatedly, so a number measured on
it is no longer a first-look estimate. It becomes development data.

## Approach

1. Generate new mutation instances (`benchmark/build.py`) from base programs
   that no existing split uses, with more interprocedural rows so the
   interprocedural comparison has enough power (target: at least 60
   interprocedural rows).
2. Run independent plausibility judging (`benchmark/judge.py`) with a model
   family that is neither Anthropic nor the detector's.
3. Write the new `test.jsonl` and regenerate `splits.manifest.json`. (The old
   test rows were already folded into `dev.jsonl` on 2026-10-07.)

## Decision needed: real-curated rows

The 43 human-annotated real-curated rows were in the old test split and are
now dev data. A fresh test split can be synthetic only, or it can include a
new real-curated portion, which needs a new round of human annotation under
`docs/annotation.md` (about 50 candidates, two independent passes). Default:
synthetic only, with the real-curated results reported from dev as repeated,
not first-look, evidence.

## Done when

The leakage check passes (no base-program group is shared with train/dev), the
class and stratum counts are recorded here, and the old test rows are part of
dev.
