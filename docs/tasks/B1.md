# B1 — Fresh held-out test split

**State:** done

## Why

The current `test.jsonl` has been evaluated repeatedly, so a number measured on
it is no longer a first-look estimate. It becomes development data.

## Approach

1. Write new seed base programs (Claude-authored, GnuCOBOL 3.2.0 batch
   programs) that no existing split uses, including multi-program and shared
   copybook bases so at least 60 rows are interprocedural, and register them
   in the build catalog.
2. Generate mutation rows from those bases only (`benchmark/build.py`),
   including benign MO-0 edits; every mutation must compile and change
   behaviour as intended.
3. Plausibility judging by Claude using `docs/judge-rubric.md`. Claude is a
   different model family from the detector (`gpt-6-luna`), which is what the
   integrity rule requires. No human annotation pass.
4. Write `test.jsonl` and regenerate `splits.manifest.json`.

Decision (2026-10-07): the fresh split is synthetic only; the 43 existing
human-annotated rows stay in dev.

## Done when

The leakage check passes (no base-program group is shared with train/dev), and
the class and stratum counts are recorded here.

## Result (2026-10-07)

- 146 seed programs in `data/benchmark/seed/programs/fresh/` (60 cross-program
  hosts: 20 copybook cutoff hosts for MO-1×, 20 validate/post gates for MO-3×,
  20 two-program step chains for MO-6×; plus 21 local hosts with their
  copybooks). `benchmark/fresh.py` discovers hosts, runs `mutate`, writes the
  exact edits to `data/benchmark/edits/`, and dedupes by visible source.
- 148 candidates; every mutation compiled under GnuCOBOL 3.2.0 and changed
  behaviour as intended.
- Claude judged all 148 against `docs/judge-rubric.md`: 145 plausible, 3
  implausible (two unindented `WS-COMPLIANCE-FLAG` wrappers that read as a
  generator fingerprint; one deleted notice test that leaves code which can
  never breach the clause). Plausible rate 98.0% (gate 90%).
- `test.jsonl`: 145 rows, 60 interprocedural.
