## Ratification — executable scope and versioning disposition (2026-08-23)

Repository inspection established that the frozen T5.4 architecture has no
independent effective-date/version filtering stage in regulation retrieval:

- `RegulationSearch` searches the complete corpus/index;
- its API accepts no version or effective-date argument;
- chunk hits are joined to clauses by `(doc, clause_id)`;
- the benchmark supplies the exact `RegulationClause` to the agent; and
- `build_hunt_prompt` exposes `clause.version` and `clause.effective_date`.

The requested versioning ablation is therefore
`NOT_INDEPENDENTLY_ABLATABLE`. Temporal identity is embedded in the frozen
input/prompt contract, not implemented as a detachable retrieval component.
Adding a version-filtered control would create a new control and violate the
frozen T5.4 identity. Hiding the two temporal fields would instead be a prompt
and input-contract ablation and may produce contract failures; it is not a
substitute. T5.5A does not experimentally estimate the contribution of version
awareness, and the paper must state that limitation.

Exactly five provider-backed configurations are authorized: `control`,
`no_slicing`, `no_execution`, `no_entailment`, and `no_reranking`. The maximum
planned execution is 355 full rows plus 35 validity-smoke rows, or 390 provider
rows. A sixth `no_versioning` configuration is prohibited.

Seed `20260823` is ratified for the panel: all 36 frozen interprocedural rows
plus five local rows independently selected from each D1-D7 gold stratum, with
the final 71 IDs restored to frozen v1 test order. The seven-row validity smoke
contains one frozen panel row per D1-D7 class. Smoke performance is not an
authorization gate and cannot motivate an implementation change.
