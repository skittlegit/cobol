# T7.3 work order — benchmark and project release packaging

**Owner:** Track B

**State:** NOT_COMPLETE; explicitly accounted in R1.7 on 2026-10-06

**Depends on:** T5.2 done for package preparation; T5.5 done for final release

**Canonical artifacts:** `release/manifest.json`, `RELEASE.md`,
`scripts/build_release.py`

## Objective

Produce a deterministic, reviewer-auditable release package containing the
frozen benchmark, documentation, annotation evidence, licenses, and
reproduction entry points without leaking local caches, corpora, credentials,
or transient evaluation artifacts.

## Required contents

1. Include `data/benchmark/v1/`, `DATASHEET.md`, `ANNOTATION.md`, the four
   locked T5.1 evidence files, `LICENSE`, regulation-source pin metadata, and
   the code revision needed to validate them.
2. Record every included path, byte size, SHA-256, role, and license in
   `release/manifest.json`. The manifest also records the git commit and the
   benchmark manifest hash.
3. State the exact frozen counts: 307 train, 102 dev, 196 test, 43
   real-curated test rows, 9 intact T6 pairs, and 8 excluded candidate IDs.
4. Explain which fields are benchmark gold and how consumers construct
   gold-hidden detector input. Do not describe the raw `DriftInstance` row as
   safe system input.
5. Include release notes that preserve the M4 `NO_GO`, the final M5 result,
   human-primary/Claude-verification provenance, T6 denominator limitation,
   and licensing/usage restrictions.
6. Exclude fetched corpora, `.model_cache`, virtual environments, credentials,
   provider request/response logs not explicitly approved for release,
   temporary smoke output, and superseded benchmark versions.

## Gates

- Two builds from the same clean commit produce identical file lists and
  content hashes.
- Every JSON/JSONL artifact validates against its current schema; every
  manifest checksum re-hashes correctly.
- The release builder fails on a dirty version identity, missing locked
  evidence, unexpected file, stale count, or checksum mismatch.
- The archive can be unpacked and its benchmark/package validation run without
  access to the developer working tree.
- `git diff --check`, the packaging tests, annotation/freeze gates, and full
  offline suite are green at the release commit.

## Publication rule

The package may be assembled and tested before M5, but the final tag/archive is
published only after T5.5 closes M5 and `RELEASE.md` contains the measured
result. A release tag never mutates benchmark v1; corrections require a new
version.
