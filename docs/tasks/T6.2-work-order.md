# T6.2 work order — isolated Luna/max migration agent

**Owners:** Track A / Track C  
**State:** reactivated 2026-08-24; blocked on T6.1 and T8.2  
**Canonical artifacts:** `src/cobol_archaeologist/migration/`,
`tests/test_migration_agent.py`, `data/migration/runs/`

## Objective

Generate auditable COBOL remediation patches from verified evidence while
keeping canonical benchmark and corpus sources immutable.

## Two evaluation tracks

1. **Detector-led:** the agent receives only a configuration-3 verified finding
   and its detector-visible evidence. This track is an end-to-end result and is
   activated only if the T8.1 utility gate passes.
2. **Oracle-assisted:** the same migration agent receives the frozen oracle
   finding. This upper-bound diagnostic runs even after detector `NO_GO` but is
   never described as end-to-end detector utility.

## Constraints

- ChatGPT-authenticated `gpt-5.6-luna`, `max`, isolated one case per task.
- Work only in a per-case staging directory; never overwrite benchmark or
  fetched corpus sources.
- Emit a patch, rationale, intended behavior, affected locations, and explicit
  abstention when safe remediation is unsupported.
- No credentials, git history, mutation provenance, hidden labels, or unrelated
  cases enter the prompt.
- Source-line fidelity and copybook/program boundaries remain explicit.

## Gates

Patches must parse, remain within allowed source scope, contain no unrelated
file changes, and be reproducible from the frozen run key. T6.3—not the model—
decides whether a patch is behaviorally valid.

## 2026-08-24 implementation checkpoint

The isolated agent contracts, staging boundary, canonical configuration-3
finding binding, run identity, and artifact validation are implemented.
Detector-led prompts omit the untrusted model-authored evidence ledger; the
oracle-assisted track remains separately labeled. Live execution is still
blocked on the T6.1 review freeze and ChatGPT authentication.
