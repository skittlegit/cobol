## Findings

1. **Host checks discard correct answers.** In 36 of the 57 abstentions, the
   model's hypothesis was correct before rejection (D1 12, D6 10, D3 6, D2 3,
   D7 3, D4 2). The most common reasons: the D1 rationale must compare against
   the current value (8), citation not entailed (13, mostly D6), D3 must name
   the conflicting outcomes (9), ledger hash mismatch (6). D1 and D2 address
   these.
2. **D6 dead code is never found (0/23).** Nine rows are called D2 ("missing
   rule") because a disabled branch looks like absent behaviour; nine more are
   rejected on citation entailment. D4 addresses this.
3. **Conformant code is called missing-rule.** 12 answered and 6 abstained D7
   rows were judged D2. D4 addresses this.
4. **Temporal pairs: 7/20.** Both sides of a pair share code, so the detector
   must judge against the clause version it is given. D4 addresses this.
5. **Interprocedural significance:** +0.26 F1 over rag_reranker on only 36
   rows, p = 0.0512. More interprocedural rows in B1 give the test enough
   power.
6. **The old splits were unbalanced.** Interprocedural rows: train 7, dev 0,
   test 36. D6: train 23 (all local), dev 0, test 23. The detector could not be
   tuned on its weakest strata without the test split. The old test rows are
   now part of dev (C1 follow-up), and B1 must spread strata across splits.
